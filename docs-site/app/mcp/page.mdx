# Agents, MCP, and plugins

Agents reach Lighthouse Memory in two ways. The hosted Memory service has an MCP endpoint: any MCP client connects to a project with that project's API key, and no code is needed. Or you serve the library's functions from your own MCP server, next to your own graph.

## The hosted MCP endpoint

The Memory service answers MCP over streamable HTTP at `/mcp`, beside its HTTP API. The hosted service is at `https://lighthouse-memory.vercel.app/mcp`; a stack you run yourself answers at its own address, such as `http://localhost:8200/mcp` on your computer. The console shows the address under **Agents & MCP**.

- **The key is the agent.** Send a project API key as a bearer token. The key chooses the project, its scopes choose what the tools may do, and its name is the agent's name in every entry, claim, and handoff. Create one key per agent and name it after the agent. A tool cannot write under another name.
- **The same rules as the HTTP API.** Each MCP request counts against the key's 120 requests a minute and shows in the project's usage. Refusals give the same short messages as the HTTP API; details stay in the service's logs.
- **What tools return is data.** Memories and entries were written by people and other agents. The server tells the model to treat them as data, never as instructions.

| Tool                                                        | Access | Does                                                     |
| ----------------------------------------------------------- | ------ | -------------------------------------------------------- |
| `remember(key, title, text, metadata, links)`               | write  | Saves a memory, or a new version of one                  |
| `recall(query)`                                             | read   | Memories whose title or text has the words, up to 100    |
| `history(key)`                                              | read   | Every version of a memory, oldest first                  |
| `connection(start, end)`                                    | read   | The shortest chain of links between two memories         |
| `open_episode(id, about)`                                   | write  | Starts an episode about memories that exist              |
| `record(episode_id, type, values, cites)`                   | write  | Adds an entry that cites its evidence                    |
| `close_episode(episode_id, outcome, cites)`                 | write  | Closes an episode with its outcome                       |
| `episode(episode_id)`, `episodes_about(key)`                | read   | One episode with its entries; the episodes about a memory |
| `add_task(id, kind, about, after)`, `claim_task(kind, lease)` | write  | Adds work; claims the oldest free task of a kind         |
| `complete_task(task_id)`, `release_task(task_id)`           | write  | Finishes or gives back a task the agent holds            |
| `hand_off(id, to, points_to, values)`, `accept_handoff(id)` | write  | Passes work to another agent; takes work given to it     |
| `handoffs(waiting)`                                         | read   | The handoffs given to this agent                         |

A key with read access only can call the read tools; a write tool answers that the key does not allow it.

## Connect a client

Replace `YOUR_PROJECT_API_KEY` with your project key, and the address with yours if you run the service yourself. The console fills both in when you create a key for an agent on its **Agents & MCP** page.

**Claude Code**, in a terminal:

```bash
claude mcp add --transport http lighthouse-memory https://lighthouse-memory.vercel.app/mcp \
  --header "Authorization: Bearer YOUR_PROJECT_API_KEY"
```

**Cursor** (`~/.cursor/mcp.json` or `.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "lighthouse-memory": {
      "url": "https://lighthouse-memory.vercel.app/mcp",
      "headers": { "Authorization": "Bearer YOUR_PROJECT_API_KEY" }
    }
  }
}
```

**Codex** (`~/.codex/config.toml`) reads the key from the environment variable it names:

```toml
[mcp_servers.lighthouse-memory]
url = "https://lighthouse-memory.vercel.app/mcp"
bearer_token_env_var = "LIGHTHOUSE_API_KEY"
```

**Claude Desktop** connects to a server that needs a header through `mcp-remote`, which needs Node.js. In `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "lighthouse-memory": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://lighthouse-memory.vercel.app/mcp",
               "--header", "Authorization: Bearer YOUR_PROJECT_API_KEY"]
    }
  }
}
```

**Your own agent**, with the MCP SDK for Python:

```bash
pip install "mcp>=1.26,<2"
```

```python
import asyncio

from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client

URL = "https://lighthouse-memory.vercel.app/mcp"
HEADERS = {"Authorization": "Bearer YOUR_PROJECT_API_KEY"}


async def main():
    async with streamablehttp_client(URL, headers=HEADERS) as (read, write, _):
        async with ClientSession(read, write) as session:
            await session.initialize()
            found = await session.call_tool("recall", {"query": "customer"})
            print(found.content[0].text)


asyncio.run(main())
```

## Plugins

A plugin adds the MCP server and a skill that tells the agent when to remember, when to recall first, and how to record work as episodes with evidence. There is one for each of Claude Code, Cursor, and Codex, in the repository's `plugins/` folder.

### Claude Code

In Claude Code:

```text
/plugin install lighthouse-memory --marketplace MitudruDutta/lighthouse
```

Before Claude Code 2.1.275, add the marketplace first: `/plugin marketplace add MitudruDutta/lighthouse`, then `/plugin install lighthouse-memory@lighthouse`. The plugin reads its address and key from the environment:

```bash
export LIGHTHOUSE_MEMORY_URL=https://lighthouse-memory.vercel.app
export LIGHTHOUSE_API_KEY=YOUR_PROJECT_API_KEY
```

The plugin lives in `plugins/claude/lighthouse-memory/`; the marketplace that lists it is `.claude-plugin/marketplace.json`.

### Cursor

Copy the plugin into Cursor's local plugins folder, then run **Developer: Reload Window**:

```bash
git clone https://github.com/MitudruDutta/lighthouse.git
mkdir -p ~/.cursor/plugins/local
cp -r lighthouse/plugins/cursor/lighthouse-memory ~/.cursor/plugins/local/
```

Set the plugin's `LIGHTHOUSE_API_KEY` variable to your project key under **Plugins**, **Configure**. A team can also import the repository as a marketplace: it lists the plugin in `.cursor-plugin/marketplace.json`.

### Codex

Add the repository as a plugin marketplace, then install the plugin from `/plugins` in Codex. Codex asks for the project API key when you install it:

```bash
codex plugin marketplace add MitudruDutta/lighthouse
```

The plugin follows the Agent Plugins format, in `plugins/codex/lighthouse-memory/`; the marketplace that lists it is `.agents/plugins/marketplace.json`.

### Your own service

The plugins connect to the hosted service at `https://lighthouse-memory.vercel.app/mcp`. For a service you run yourself, change `url` in the Cursor or Codex plugin's `mcp.json`, or set `LIGHTHOUSE_MEMORY_URL` for the Claude Code plugin.

## Your own MCP server on the library

With the library, you choose the graph, the kinds, and the tools. This wrapper serves the state and history of one kind over standard input and output. The MCP SDK is not a dependency of the library; install it beside it, and keep to version 1, since version 2 renamed the classes used here:

```bash
pip install lighthouse-graph "mcp>=1.26,<2"
```

```python
import json
import os
from falkordb import FalkorDB
from mcp.server.fastmcp import FastMCP
from lighthouse import Kind, as_of, ensure_schema, history, now

DEVICE = Kind("Device", key="serial", text=("note",))
graph = FalkorDB(
    host=os.environ.get("FALKORDB_HOST", "127.0.0.1"),
    port=int(os.environ.get("FALKORDB_PORT", "6379")),
).select_graph("equipment-memory")
ensure_schema(graph, [DEVICE])
server = FastMCP("equipment-memory")

@server.tool()
def device_state(serial: str, at: str | None = None) -> str:
    """Read a device now or at a UTC timestamp."""
    return json.dumps(as_of(graph, DEVICE, serial, at or now()), default=str)

@server.tool()
def device_history(serial: str) -> str:
    """Read the recorded state changes of a device."""
    return json.dumps(history(graph, DEVICE, serial), default=str)

if __name__ == "__main__":
    server.run(transport="stdio")
```

| Agent needs                              | Library functions                                    |
| ---------------------------------------- | ---------------------------------------------------- |
| Resolve an entity from text              | `search()`, `search_history()`                       |
| Inspect state and changes                | `as_of()`, `history()`, `related()`                  |
| Follow shared evidence                   | `pointing_at()`, `similar()`, `connection()`         |
| Inspect a group or structural importance | `groups()`, `important()`                            |
| Read prior outcomes                      | `episode()`, `lessons_about()`, `playbooks_for()`    |
| Check what rested on a fact              | `impact_of_entry()`, `diff_between()`                |
| Append a decision or hand off work       | `record()`, `add_task()`, `hand_off()`               |

Choose the graph from an authenticated identity before a tool runs, and set the agent's name in server code. Do not accept raw queries, graph names, credentials, or agent names from a model's arguments. Bound the results and the number of calls, catch infrastructure errors in the wrapper, and give the agent a short explanation; keep diagnostics in your logs.

See [model integration](/integrations), [audit and time travel](/audit), [security](/security), and the [official MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk).
